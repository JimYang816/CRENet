# 四数据符号 LMMSE 小实验

当前小实验使用 `configs/data/{nof1,ncs1}/dddd.json` 与
`configs/evaluation/four_data_lmmse.json`。两条信道使用相同的 D-D-D-D 帧、
1024 点 FFT、256 点循环前缀、512 个数据子载波、256 个梳状导频、128 个带内保护空载波和两侧各 64 个边缘空载波。
时间域 DPSS 基跨完整帧和循环前缀，半带宽 12 Hz，固定 Q=24、延迟支撑 L=176。
其余链路参数和模型误差比率 0.03 沿用原配置。先验使用独立记录 51–55；
测试使用已定义测试划分中的记录 11、15、19、23、27，各取 2 s 处一帧。

四个数据符号的梳状导频与保护空载波共同用于无反馈联合 CSI 估计。
均衡直接使用该估计，不按参考 CSI 或目标 NMSE 缩放。先验从独立记录的物理信道构造；
测试帧的参考 CSI 只用于理想参考均衡和 NMSE 评分。两种 CSI 使用相同发射数据和噪声。
单抽头算法沿用数据载波原始观测；完整矩阵算法消除已知导频，使用全部接收载波和有色噪声协方差。
SNR 为四个数据符号接收有用窗平均功率与滤波后预期热噪声功率之比。

```bash
python -m scripts.evaluate.four_data_lmmse --device cuda --threads 4
```

默认写入 `outputs/smoke/four_data_lmmse/`，包括实验与代码身份、各帧物理数据、
逐帧误码及模型诊断、`summary.csv`、`ber_snr.png/pdf` 和 `nmse_snr.png/pdf`。
每条信道每个 SNR 为 20,480 个比特；结果是小样本诊断，不是正式性能结论。
NMSE 为每帧每数据符号完整信道矩阵的线性 NMSE 先平均、再取 dB。参考 CSI 相对于自身
的 NMSE 为 0，dB 值为负无穷，因此图中以文字注明。BER 图中的空心点表示零实测误码，
绘制在半个误码的计数下限；表格仍记录真实零值。

历史 P-D-D-P 压缩数据及基于该帧训练的检查点并不适用于本实验；该入口不会读取它们。
若需后续正式训练，须先为新帧生成并验证对应的数据集和划分。

当前 CP=256、Q=24 时，12 Hz DPSS 累计尾能量比约为 `5.60e-5`，高于配置中的 `1e-5` 自动选阶阈值；
固定 Q=24 优先，阈值只作为诊断，不改变指定阶数。

当前保留的小实验结果位于 `outputs/smoke/four_data_cp256_q24_20261123/`；
完整物理波形保留在服务器的同名目录。本轮旧 CP/Q 实验的波形、结果和对比图已清理。
历史对比脚本仍可作为研究工具，其输入必须通过物理参数及来源校验。

## NCS1 的 64 抽头支撑诊断

```bash
python -m scripts.evaluate.ncs1_delay_support --tap-count 64 --device cpu --smoke --output outputs/smoke/ncs1_delay64_local
python -m scripts.evaluate.ncs1_delay_support --tap-count 64 --device cuda --threads 4 --output outputs/smoke/ncs1_delay64
```

该入口固定当前 CP=256、12 Hz、Q=24、512 数据和 256 导频，比较原连续 176 点、
前 64 点、先验能量最大的连续 64 点窗口、先验平均功率最大的离散 64 点。
后三者只有 64 个待估时延系数列，保留实际时延位置，离散支撑跨度可以大于 64。
选择抽头和估计先验均仅使用独立记录 51–55 的 2、8、14、20、26 s 窗口；
测试固定为记录 11、15、19、23、27 的 2 s 帧，各方案使用相同数据、噪声及原始 CSI 估计方式。
CPU 冒烟模式仅取两帧先验和一帧测试，在 0、15、30 dB 验证链路。

输出包含原生与接收机等效 PDP、冻结的支撑索引、先验和测试覆盖能量、
含全部遗漏时延分量的平均完整矩阵 NMSE-SNR、两种 LMMSE 的 BER-SNR、
系数数量和运行时间。测试参考 CSI 仅用于评分和理想检测；逐符号最优 64 点能量覆盖率
及覆盖 90%/95%/99% 能量的最少点数也仅为评分后的理想界，不能作为接收机性能。
该研究不修改两条信道共用的正式 D-D-D-D 配置，也不将局部抽头误差冒充完整信道 NMSE。

2026-11-24 的配对结果位于 `outputs/smoke/ncs1_delay64_20261124/`，计算代码为
`ca1fc2e`，完整物理数据保留在服务器同名目录。每个 SNR 共 20,480 bit。
本表的 L=176 基线也使用同一组 25 个先验窗口重新计算，不直接沿用之前仅用 5 个先验窗口的指标。

| 支撑方案（索引从 0 开始） | 测试平均能量覆盖 | 30 dB 完整矩阵 NMSE | 30 dB Full-matrix BER |
| --- | ---: | ---: | ---: |
| 连续 0–175，176 点 | 92.09% | -4.286 dB | 0.14688 |
| 连续 0–63，64 点 | 65.71% | -3.270 dB | 0.18052 |
| 先验最优连续窗口 35–98，64 点 | 76.33% | -3.727 dB | 0.16499 |
| 先验功率最大的离散 64 点 | 76.30% | -3.715 dB | 0.16274 |

主径约在原始时延 1 ms、接收机时延索引 38 附近；离散方案的具体索引保存在
`selected_support.json`。64 点将 Q×L 从 4224 降到 1536，减少 63.6%，但本次并未改善
完整信道估计和 BER。即使在评分阶段允许为每个测试符号理想地重选 64 点，平均也仅覆盖
80.35% 能量；理想覆盖 90%/95%/99% 能量平均至少需 106.55/138.75/176.00 点。
这只是本次 5 帧测试的理想界，不是可实现的接收机选点方法。当前结果不支持将正式配置改为 64 点。

## NCS1 的固定 176 点离散支撑实验

NCS1 支撑实验默认读取 `configs/evaluation/ncs1_delay_support.json`，选择 176 个离散抽头，
具体位置冻结在 `configs/data/ncs1/delay_support176.json`。这些位置直接取自上述 25 个独立先验窗口
的平均物理 PDP，不因测试帧或 CPU 冒烟批次改变。配置同时记录原始归档哈希、帧配置哈希、
源代码版本和先验窗口，运行前验证来源、数量、位置及记录划分。

```bash
python -m scripts.evaluate.ncs1_delay_support --device cpu --smoke --output outputs/smoke/ncs1_delay176_local
python -m scripts.evaluate.ncs1_delay_support --device cuda --threads 4 --output outputs/smoke/ncs1_delay176
```

新对比仅包含连续 0–175 点与冻结的离散 176 点，两者待估系数均为 Q×L=24×176=4224。
离散位置从索引 33 延伸到 220，重建的时延跨度为 221；不能将压缩后的 176 列当作连续 0–175 点。
两者使用相同的 25 个先验窗口、5 个测试帧、发射数据、噪声、DPSS、模型误差项和无反馈 CSI 估计。
平均完整矩阵 NMSE 包含所有遗漏的时延分量；输出也记录最差符号覆盖率及两种 LMMSE 的 BER。
本配置用于当前 NCS1 支撑对比入口；两条信道共用的 `dddd.json` 帧基准和历史实验保持各自来源身份。

2026-11-24 的计算结果位于 `outputs/smoke/ncs1_delay176_20261124/`，计算代码版本为 `0599e1a`。
本地 CPU 小样本和相关回归测试通过，服务器 CUDA 上 13 项接收机及检测器测试通过。
完整计算使用相同的 25 个先验窗口、5 个测试帧，扫描 0–30 dB，每个 SNR 为 20,480 bit。
冻结索引与本轮重新计算的独立先验功率排序完全一致；连续基线和理想参考误码计数也复现了上轮结果。

| 指标 | 连续 0–175 点 | 固定离散 176 点 |
| --- | ---: | ---: |
| 测试平均能量覆盖 | 92.09% | 97.50% |
| 测试最差符号能量覆盖 | 88.82% | 96.26% |
| 30 dB 完整矩阵平均 NMSE | -4.286 dB | -4.402 dB |
| 30 dB Single-tap BER | 0.17617 | 0.17031 |
| 30 dB Full-matrix BER | 0.14688 | 0.13843 |

这批小样本中，离散方案的 20 个测试符号均覆盖超过 95% 的能量。30 dB NMSE 改善约 0.117 dB，
Full-matrix BER 相对下降约 5.75%；0 dB 的 Full-matrix BER 基本相同且离散方案略高。
提升幅度有限，不能仅凭更高的能量覆盖宣称已解决 CSI 估计误差；这里也没有减少相对连续 L=176 的待估参数量。
逐 SNR 的指标见 `summary.csv`，图表为 `ber_snr.png/pdf`、`nmse_snr.png/pdf` 和 `delay_profile.png/pdf`。

### 增加离散抽头数的配对扫描

```bash
python -m scripts.evaluate.ncs1_delay_support --sweep-counts 176 184 192 208 --device cuda --threads 4 --output outputs/smoke/ncs1_delay_count_sweep
```

该入口在同一物理数据上比较连续 L=176 和离散 176、184、192、208 点，保持已冻结的 176 点作为公共子集，
再按独立先验平均 PDP 排序补充抽头。所有支撑在读取测试参考 CSI 前固定；单次运行只生成一份配对物理数据。
原来的 176 点默认配置不变。输出包含逐 SNR 的 BER、完整矩阵平均 NMSE 和能量覆盖统计，
以及最高 SNR 下 NMSE/BER 随抽头数量变化的 `tap_count_tradeoff.png/pdf`。测试扫描只用于诊断收益，
不自动根据这批测试帧修改默认抽头数。

2026-11-24 扫描结果保存在 `outputs/smoke/ncs1_delay_count_20261124/`，计算代码为 `93484fb`。
使用相同的 25 个独立先验窗口和 5 个测试帧，每个 SNR 20,480 bit；服务器 14 项相关测试通过。
连续 176 点、离散 176 点及理想参考均复现上轮完整曲线，新增支撑也逐一核对为同一独立先验排序的前 K 点。

| 离散抽头数 | 待估系数 | 测试平均能量覆盖 | 30 dB 完整矩阵平均 NMSE | 30 dB Full-matrix BER |
| --- | ---: | ---: | ---: | ---: |
| 176 | 4224 | 97.498% | -4.4025 dB | 0.13843 |
| 184 | 4416 | 98.838% | -4.4410 dB | 0.13696 |
| 192 | 4608 | 99.974% | -4.4692 dB | 0.13633 |
| 208 | 4992 | 99.999985% | -4.4694 dB | 0.13657 |

176→192 的 30 dB NMSE 改善约 0.0667 dB，待估系数增加 9.09%；192→208 只再改善约 0.0002 dB，
且 30 dB BER 略升。NMSE 在所扫描 SNR 上随点数增加均略降，但低 SNR 的 BER 并非单调改善。
在这批诊断样本中，192 点之后收益基本饱和；默认仍为先前配置的离散 176 点，不能把测试扫描的最佳点数
直接当作已通过独立验证集选择的最终配置。图表保留完整 SNR 曲线及抽头数量的收益曲线。

## 参考 CSI 辅助的 5 dB 误差补偿实验

为研究 CSI 误差降低时的均衡表现，可单独运行：

```bash
python -m scripts.evaluate.four_data_csi_compensation --device cuda --threads 4
```

该实验读取上述 CP=256、Q=24 物理数据，重新计算原始 CSI 并核对原始及参考 CSI 的误码。
对每帧、每个 SNR 和每个数据符号，将原始 CSI 补零到参考矩阵的完整延迟支撑后构造
`H_assisted = H_ref + 10^(-5/20) * (H_raw - H_ref)`，使每个完整信道矩阵的 NMSE
相对原始值降低 5 dB。完整支撑包含原 L=176 之外的参考分量。两种 LMMSE 共用原接收观测、
导频和噪声；结果与原始和参考 CSI 一并绘制，输出独立存放，不覆盖原始实验。
该构造使用测试样本的参考 CSI，属于理想辅助的敏感性实验，不能作为实际接收机估计性能。
